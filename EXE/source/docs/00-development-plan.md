# AI小说生成器 9.0 EXE 独立项目开发计划

## 目标

在独立目录构建 9.0 EXE：以 9.0 HTML 细分源码作为 renderer 业务主线，接入 IndexedDB 主存储，并保留旧 EXE 的 Electron 特色能力。旧 8.9 EXE 项目、包体、原始源码和用户数据只读。

## 阶段

1. **源码合并与启动链**：把 9.0 细分 renderer 与已验证的 IDB/Electron 适配合并，完成异步启动、旧 localStorage 迁移和快照恢复。
2. **保存边界与清理**：补齐所有关键保存点的事务等待、初始化清空、快照墓碑和失败回滚。
3. **版本化构建**：所有构建脚本、测试夹具、Electron metadata、输出目录统一为 9.0。
4. **回归审查**：执行完整脚本语法、浏览器迁移/重载/备份/大数据测试、Electron IPC/UI/单实例测试，并与旧 EXE 做 DOM、按钮、IPC、preload bridge 对比。
5. **发布前封存**：记录产物哈希、旧包体哈希、测试结果和剩余边界，生成独立 9.0 包体。

## 当前风险与处理状态

- IndexedDB 写入是异步事务，`saveAll()` 的同步返回值只能表示已排队；本阶段已在切书、切章、生成、导入、关闭前及重写、润色、摘要/成长、吐槽、冲突检测、章节排序、起书、API 重试和回滚等边界加入提交等待。
- Electron 快照只作为恢复/便携通道，并以 IndexedDB 最近成功提交时间判断是否允许回填；已通过新旧时间戳和旧格式快照测试。
- 清空流程同时清理 IndexedDB、localStorage 兼容键和 Electron 快照；快照删除失败时写入空墓碑，已通过清空逻辑审查。
- 单实例、托盘、窗口和 UI smoke 必须串行执行；本阶段已串行通过真实 Electron IPC/UI 测试。

## 断点续传规则

每完成一个阶段，更新 `01-project-memory.md`；每次发现工具、构建、迁移或竞态问题，更新 `02-lessons-and-pitfalls.md`。测试日志区分静态检查、浏览器模拟和真实 Electron 验证。

## 2026-10-16 收尾结果

- 阶段 1 至阶段 4 已完成，阶段 5 已生成独立包体并记录哈希。
- 旧 8.9 EXE 包体未写入；9.0 输出目录为 `dist/AI小说生成器9.0-IDB独立版/`。
- 发布前限制：本阶段未连接真实 API 做付费生成回归，API 相关验证限于配置、保存边界和既有离线夹具。
